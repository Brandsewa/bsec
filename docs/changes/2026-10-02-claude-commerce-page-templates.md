# Cart as a theme page, sticky buy box and the Modern Commerce draft theme

- **Date:** 2026-10-02
- **Agent:** claude
- **Branch:** `feat/commerce-page-templates` (not merged yet)
- **Area:** blocks, block-editor, domain, web, superadmin, admin
- **Type:** feature
- **Supersedes:** none

## Summary
The collection and product pages could already be laid out per theme, but the cart was a hardcoded component. The cart is now a fifth theme page with a `CartContents` core block, so a theme can design the cart page without touching cart logic. A "Modern Commerce" draft theme carries one best-practice layout each for collection, product and cart. Checkout is unchanged on purpose.

## What changed
- `cart` theme system page (`cart_template`, `template-cart`): `packages/blocks/src/theme-pages.ts`; stores copy it on theme activation like the other pages (no migration: `pages.type` is free text).
- `CartContents` block (schema, view, editor panel, `RenderContext.renderCartContents`): `packages/blocks`, `packages/block-editor/src/config.tsx`. `ProductDetail.stickyBuyBox` added (optional, default false).
- Storefront: `apps/web/src/app/cart/page.tsx` renders the store's cart template when published, built-in layout otherwise; `CartView` takes layout options; `ProductDetailSection` honours `stickyBuyBox`.
- Super Admin theme editor has a "Cart page" tab; the store admin Themes screen lists the cart page; `starterPages()` in `themes/templates.ts` includes a cart.
- Seed: `packages/domain/src/themes/commerce-templates.ts` (layouts) and `seed-commerce-templates.ts`; run `STAFF_EMAIL=... pnpm --filter @bs/platform seed:templates`. Creates or refreshes the **unpublished draft** `modern-commerce` and audits it.

- **Conversion settings (all optional, defaults keep the old look):** collection: phone columns, image shape, card style, sale badge, ratings, breadcrumb; product: SKU toggle, reassurance lines, phone sticky price/add-to-cart bar (`MobileBuyBar`); cart: heading, checkout label, free-shipping progress bar, reassurance lines, phone sticky checkout bar, continue-shopping link. Editor panels in `block-editor/src/config.tsx`.
- **Free-shipping bar** reads the store's own rule via `getFreeShippingThresholdPaise` (`orders/shipping-rates.ts`); nothing is hardcoded in the template (rule 12) and checkout still prices shipping itself.
- **Storefront colour fix:** the cart, product and collection components use classes such as `bg-primary` and `border-border` that no stylesheet defined, so buttons and cards rendered unstyled. `globals.css` now maps them to the store's theme colours, **only inside a `.bs-skin` wrapper** that the cart, product and collection pages add. Checkout and account pages are not wrapped and look exactly as before.

- **Theme library states (Super Admin > Themes):** tabs Published / Drafts / Archive. "Hide" became "Archive" (`updateMeta { archived }`), archived themes can move back to Drafts, and Delete (`templates.delete`, audited) exists for drafts and archived themes only. Migration `0020_theme_template_archive` adds nullable `theme_templates.archived_at` (expand-only; previously published-then-hidden themes are backfilled as archived). Deleting never touches store copies.

- **Theme settings moved into the page editor (Super Admin):** the top-bar "Theme settings" tab is gone. Every page's editor sidebar now has a "Theme" tab, listed first in the rail above Blocks and Outline (Blocks stays the tab that opens), with collapsible sections Colours, Fonts, Corners and Buttons (`ThemeSettingsPanel` in `packages/block-editor/src/ThemeSettings.tsx`; a new settings group is a new `Section`). The tokens are global to the theme: editing them on any page restyles every page's canvas. `BlockEditor` takes optional `themeTokens` / `onThemeTokensChange`; the store admin's page editor and its separate Theme settings screen are unchanged.

- **Responsive heading sizes (Theme > Fonts > Heading sizes):** H1 to H6, each with a Desktop, Tablet and Mobile size in pixels (12 to 120), stored in the theme tokens as `fontSizes`. `computeThemeTokens` sanitises them (numbers only, clamped, default where unusable) and emits 18 `--bs-hN-d/-t/-m` rem variables; `blocks.css` applies them mobile-first (mobile below 768px, tablet from 768px, desktop from 1024px) so the editor's Mobile/Tablet/Desktop previews and real devices agree. The Heading block now supports H1 to H6 and a size "Match the heading level" (`auto`); the older Small/Medium/Large/Extra large steps map to H4/H3/H2/H1, and the defaults equal the old fixed sizes, so existing pages look the same until sizes are changed. Rich text headings follow the same sizes. Page titles inside the built-in cart, product and collection components keep their own sizes.

- **Editor preview switcher:** now ordered Desktop, Tablet, Mobile with matching monitor/tablet/phone icons (it was Mobile first with look-alike icons), labelled with the width (1280, 768 and 375px) and opening on Desktop. The widths sit on the correct side of the stylesheet's breakpoints (tablet from 768px, desktop from 1024px), so each preview applies the same rules as a real device.

- **One toolbar in the page editor:** Puck's header is replaced by `EditorHeader` (`block-editor/src/EditorHeader.tsx`), a single responsive row: back link ("Themes" in Super Admin, "Exit" in the store admin), sidebar toggles, a page switcher dropdown (Home, Collection, Product, Cart, Header, Footer in Super Admin), then status, undo/redo, Save draft and Publish. Super Admin's own top bar (a second Save draft / Publish theme pair) is gone: the toolbar's buttons save and publish the whole theme. Below 1100px the status line hides, below 900px buttons become icons, below 720px undo/redo hides; the sidebar toggles always stay (they open the sidebars on a phone).

- **Font weights and button colours (Theme tab):** Fonts has a Heading weight and a Body weight (Regular 400, Medium 500, Semibold 600, Bold 700 - the weights the Google Fonts request loads), stored as `fonts.headingWeight/bodyWeight` and emitted as `--bs-heading-weight` / `--bs-body-weight`. Buttons has a Dark button (background, text) and a Light button (background, text): `buttons.darkBg/darkText/lightBg/lightText`, only stored when set (unset follows the brand colours, with a Reset link). The dark colours drive the main button and the outline/soft styles and the storefront's cart/product call-to-action buttons (via the `.bs-skin` primary colours); the light colours drive the secondary button variant. Every colour in the panel is now a round swatch (`ColorField`). Defaults reproduce the previous look.

- **Compact builder density:** `block-editor/src/compact.ts` sets Puck's field metrics (`--puck-field-space-*`, `--puck-field-font-size`, radius) and overrides its hashed classes: block-list pills 6px/10px padding at 12px text, fields about 28px high at 12px, labels 11px, field groups with 8px padding, category headings 11px. The theme panel's own inputs, dropdowns, size boxes, swatches (26px) and accordion headers follow the same scale. It applies to every editor that uses `BlockEditor` (Super Admin and the store admin).

- **Hero slider widget + theme button size:** new `HeroSlider` block (schema in `registry.ts`, view in `views.tsx`, styles in `blocks.css`, client behaviour `apps/web/src/components/blocks/HeroSliderClient.tsx`, editor panel in `config.tsx`). Layout as in the reference: heading and subheading bottom-left, two buttons bottom-right (stacked on phones, side by side in one row), an eased bottom shade (strength and height settable) over an image and/or muted looping video background. Settings are grouped in accordion sections: Slides, Layout and text, Background and shade, Buttons, Autoplay and loop, Pagination dots, Arrows. Buttons can follow the theme (dark/light/outline, "Match theme" size) or take their own size and #rrggbb colours. Theme > Buttons gained Size (Small/Medium/Large); the Button block gained "Match theme" size. Heights and layout are responsive (tablet from 768px, desktop from 1024px); slide changes use a native scroll-snap track and one small effect, with autoplay paused when hidden, off screen, hovered, focused, touched or when reduced motion is preferred.

- **Readable save errors:** `validateTemplatePages` now throws `Bad Request: ...`, which the platform API maps to a 400 with the real reason (for example "slides.0.videoUrl: Use a direct .mp4 or .webm https link") instead of an "Internal server error". After adding a block type, restart the platform dev server: a running one that predates the block rejects pages containing it.

- **Theme preview links:** a Preview button in the editor toolbar (next to Save draft and Publish). It saves the draft, creates a temporary share link and opens it in a new tab (also copied to the clipboard). The link is `/preview/<11-char code>?page=<page>` on the marketing host, valid 24 h, noindex, and shows the theme as a snapshot with sample data and a page switcher (Home, Collection, Product, Cart). New table `theme_previews` (migration `0021`, the web role is read-only on it), `domain/src/themes/previews.ts`, contract `templates.createPreview` (audited as `theme_template.preview_create`), env `PREVIEW_BASE_URL` for the link's base (see DEPLOYMENT.md), and a `/preview/` allowance for the marketing host in the web middleware. The editor's `BlockEditor` takes a generic `onPreview` (saves, opens the tab synchronously so pop-up blockers allow it, then sends it to the returned URL); the store admin can use the same prop later for its live pages.

- **Product showcase widget + BCOM widgets group:** new `ProductShowcase` block (`registry.ts`, `views.tsx`, `blocks.css`, behaviour in `apps/web/src/components/blocks/ProductShowcaseClient.tsx`, panel in `config.tsx`, data in `domain/src/themes/block-data.ts`). Tabs (collections, newest or featured) appear only with two or more; the card rows are an array you drag to reorder and switch on or off; plus badges, compare price, "Starts from", image shape, card style, title/price sizes, cards per row per device, arrows, dots and optional autoplay. The round cart button on the image adds single-variant products through `/api/storefront/cart/items` (and updates the header cart) and sends multi-variant products to their page. The block list has a new **BCOM widgets** accordion holding the Hero slider and the Product showcase. Super Admin's editor now previews data blocks with the shared `buildSampleRenderData` (also used by theme previews).

- **Per-device layout panel on the BCOM widgets (replaces the earlier width/padding fields):** the **Section** accordion of the Hero slider and Product showcase is a page-builder style panel (`block-editor/src/LayoutField.tsx`) stored as one `box` prop (`blocks/src/layout.ts`): Margin (top, left, right, bottom) and Padding, typed with their unit (no unit dropdowns: `24px`, `1.5rem`, `2em`, `50%` for widths; a bare number means px; an info icon next to "Spacing" shows the hint in a hover pop-up; invalid text is outlined red and not applied); Sizing: Width, Min. width, Max. width (px, %, rem, em or a keyword), Height, Min. height, Max. height (px, rem, em, or auto/none) and Aspect ratio. Desktop holds the base values; Tablet and Mobile tabs (which also switch the canvas preview) hold overrides, empty fields inherit from the larger device and show the inherited value as the placeholder (a dot marks a device that has overrides, Reset clears one). Values are validated lengths only (no calc, vw or free CSS). `blocks.css` reads them as `--l-d-*`, `--l-t-*`, `--l-m-*` with desktop as the base, tablet at 1023px and below, phone at 767px and below. On the slider, height, min/max height and aspect ratio apply to the slides (an aspect ratio frees the preset slide height). Defaults keep the previous look (slider: none; showcase: 64px top and bottom padding, 48px on phones). Other settings moved out of the old Layout accordion (the word is kept free for a later setting): the slider's heading size and heading tag are in **Slides**, its text arrangement, alignment, vertical position, slide height preset and content width are in a new **Text and buttons** accordion, and the showcase's cards per row and gap are in a new **Cards per row** accordion. The `padTop*`/`padBottom*`/`sectionWidth`/`maxWidth` props from the previous iteration were never released and are gone; a draft that used them loses those values.

## Decisions and trade-offs
- Cart and checkout are not free-form block pages: money logic stays in code (rule 12). The template only places the real cart and chooses enumerated layout options. Checkout is not a theme page. See ADR-018 update.
- No new accordion, gallery or buy-box blocks: the existing `FAQ`, `UspStrip`, `Reviews` and `ProductCarousel` blocks cover those needs. The product carousel is still CSS scroll-snap only (no arrows or autoplay); a client-side slider is a follow-up.
- **Publishing a template does not change stores that already use it** (ADR-018: stores own their copy). They see "Update available" in Themes and apply it; the Super Admin publish message now says so. Automatic roll-out was not built: the platform process cannot invalidate the web process' cache (`revalidateTag`), so it needs its own design.
- The seed is a dev/operator tool, not a migration, so production themes do not change on deploy.
