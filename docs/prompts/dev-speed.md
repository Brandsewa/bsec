## Measured background (Claude, 2026-10-03)
Heavy suite locally: about 10 to 12 minutes with one Testcontainers Postgres per file; **244 seconds** with the existing shared-Postgres mode (`TEST_PG_ADMIN_URL`, `docker-compose.test-db.yml`); about 4.5 minutes in CI. The fast mode had two problems: a Windows worker crash (exit code 3221226505) in one file per run (it was `queue-consumers.int.test.ts`), and about 10 "terminating connection due to administrator command" unhandled errors (code 57P01) that make the run exit non-zero even when every test passes. Docs-only PRs run the whole heavy suite (about 5 minutes) for nothing.

## Step 1 (item 2): make the fast local test mode the default
1. **`pnpm test:heavy:local`** (root script backed by `scripts/test-heavy-local.mjs`, cross-platform Node, no bash-isms): start `docker-compose.test-db.yml` if it is not already healthy (wait for readiness with a timeout and a clear error if Docker is not running), set `TEST_PG_ADMIN_URL`, run `pnpm --filter @bs/domain test:heavy`, print the elapsed time, leave the container running (a `--down` flag removes it). Same for `@bs/db` if it has heavy tests. `pnpm test:heavy` and CI behaviour must not change.
2. **`pnpm test:affected`**: run only the tests related to files changed against `origin/main` (use `vitest --changed origin/main` or `vitest related` per package; unit and, with `--heavy`, the int tests that import a changed file). It must fall back to the full package suite when `package.json`, a migration, the schema, `packages/db/test-support` or the lockfile changed, and say so.
3. **Fix the fast-mode teardown errors.** Find why connections get terminated (the per-file database is dropped while a pool, a pg-boss instance or a runtime is still open) and close them before the drop (an `afterAll` ordering fix in the setup file or a drop that first terminates and waits, whichever is correct). The run must exit 0 when all tests pass. Do not hide errors with a vitest `dangerouslyIgnoreUnhandledErrors`.
4. **Investigate the worker crash `3221226505`** (a native crash on Windows, 0xC0000409) for at most about 90 minutes: find which file and which native module or call triggers it (candidates: pg-boss, `pg-native`, `sharp`, `bcrypt`/`argon2`, a worker memory limit), try `--pool=threads` versus forks, and a lower `maxWorkers`. Report what you found. If you cannot fix it, do not mask it; document the cause and the safe rerun rule in `docs/FAST-LOCAL-TESTS.md`.
5. Document all of it in `docs/FAST-LOCAL-TESTS.md` and in `AGENTS.md` section 4 (the command list only): the local loop is `pnpm test:affected`, then `pnpm test:heavy:local` once before pushing; CI runs the full suite.
6. **Measure and report** wall-clock before and after for: `pnpm --filter @bs/domain test:heavy` (Testcontainers), `pnpm test:heavy:local`, and `pnpm test:affected` on a one-file change.

## Step 2 (item 3): CI waits
Edit `.github/workflows/ci.yml` only in these ways:
1. **Docs-only fast path.** A PR whose changed files are all under `docs/`, `*.md` or `.github/ISSUE_TEMPLATE` (no `packages/`, `apps/`, `scripts/`, `infra/`, workflow, lockfile or config file) skips the heavy suite, the build and the unit tests. **Keep every required job name reporting success** (use a first "changes" job that outputs `docs_only`, and give the expensive steps an `if:`, so the job itself still completes green; do not use workflow-level `paths-ignore`, which leaves required checks pending forever). Always run `docs:check` and `secret-scan` on a docs-only PR. A push to `main` always runs everything, never the fast path.
2. **Fail fast ordering** in the unit job: `docs:check` and `lint` before `build`; keep `typecheck`. Do not change what is checked.
3. Confirm concurrency already cancels superseded runs on the same PR (`concurrency` group); add it if missing.
4. Test it for real: open the PR as a code PR first, and show in the PR description a second run on a docs-only commit (or a throwaway docs-only branch you delete) that the fast path runs in about a minute and the check names are all green. State exactly what you did and did not exercise.
5. **Owner actions, do not attempt them yourself:** list in the change record that the owner can enable "Allow auto-merge" and require the CI checks in GitHub (Settings, Branches) so a green PR merges without waiting for a person.

## Step 3 (item 4): guards that stop the repeated mistakes
1. **ESLint rule `bs/no-service-call-in-tx`** (same style, location and RuleTester tests as the other `bs/` rules). Inside the callback passed to `withTenant(...)` (or `db.transaction(...)`), report any call that passes the runtime identifier `rt` as an argument (that is a domain service opening its own transaction and not seeing uncommitted rows) and any `invalidateCache(...)` call (it must run after commit). Message: "Commit first, then read or invalidate; a service called inside a transaction opens its own." Allowed: passing `tx`; the existing pattern `{ _db: { db: tx } } as unknown as Runtime` (a deliberate wrapper). Run the rule across the repo: fix real violations by moving the call after the commit (behaviour must stay the same and tests must pass) and list each in the change record; for any you cannot safely move, add a line to a small checked-in baseline file with a `TODO` and the reason, never an inline `eslint-disable`.
2. **Test factories** in `packages/domain/test/helpers/factories.ts` (extend `primary-category.ts`): `createActiveProduct(rt, ctx, { price?, stock?, title? })` (category, product, variant and opening stock in one call), `createDeliveredCodOrder(...)` and `createGuestCheckout(...)` for the common order and checkout setups, each returning ids. Convert at least six existing `*.int.test.ts` files to use them where it removes boilerplate, without changing what they assert; document the factories at the top of the file and in `docs/FAST-LOCAL-TESTS.md`.
3. **Scaffold for a new admin procedure:** `pnpm scaffold:admin-procedure <router> <name> [--write]` (Node script). It creates `packages/domain/src/<area>/<name>.ts` (a service with `assertPermission`, `withTenant`, an `audit_logs` write, commit-then-read, TODO markers) and `packages/domain/test/<name>.int.test.ts` (a real-database test skeleton with a cross-store isolation case), and **prints the exact snippets** to paste into `packages/contracts/src/admin.ts`, `apps/web/src/server/api.ts`, the `case` map in `packages/domain/test/isolation.int.test.ts` and the `docs/ARCHITECTURE.md` API table. It must not edit those four shared files itself. Without `--write` it only prints. Add a unit test for the generator output.
4. **`pnpm gate:quick`**: `pnpm typecheck`, `pnpm lint`, `pnpm docs:check`, then `pnpm test:affected`. It exits non-zero on the first failure and prints the elapsed time. Document it as the pre-push command; `pnpm typecheck` and the rest of the full gate stay as they are.
