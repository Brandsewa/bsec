## 2. HIGH: return photo upload is open to anyone (security)
Files: `apps/web/src/app/api/storefront/orders/[token]/return/photo/route.ts`, `.../photo/finalize/route.ts`, `packages/domain/src/orders/return-photos.ts`. Violates plan section 3.3. Fix all of these:
1. **The order token is never checked.** Both routes read `token` into `_token` and ignore it. Require a valid order action token (or the signed-in customer who owns the order) and resolve the real `orderId` from it. The presign route currently uses `orderId: crypto.randomUUID()`, so keys are not tied to any order.
2. **The finalize route trusts the client.** `storageKey`, `mime` and `bytes` come from the request body and a `media` row is inserted for whatever key is sent. A client can register an arbitrary object, including one belonging to another tenant, and the admin would then receive a signed download URL for it. Finalize must (a) require the key to start with `tenants/<tenantId>/returns/<orderId>/`, (b) look up the real object (`HeadObject`), and take size and content type from storage, never from the request, (c) read the first bytes and reject unless they are real JPEG, PNG or WebP.
3. **The magic-byte check fails open.** Any error other than a `Bad Request` is swallowed ("continue with header validation") and the check is skipped entirely when R2 credentials are missing. It must fail closed: a missing object or an R2 error refuses the photo. Tests may inject a fake storage client; production behaviour must not depend on credentials being absent.
4. **Rate limit is tenant-wide** (`checkStorefrontRateLimit(db, tenantId)`), so one visitor can exhaust it for everyone, and it is not per order or per IP. Add per-order and per-IP limits (plan: 20 uploads per hour per order).
5. **Enforce the limits on the server**: at most 5 photos per return, 5 MB, JPEG, PNG, WebP only (no SVG, HTML, GIF).
6. **Attaching photos to a return**: in `requestReturn`, the client sends photo ids (`input.photos.slice(0,5)`) that are stored without any check. Accept only media ids that were finalized for **this order**, in this tenant, with folder `returns`, and not already attached to another return.
7. **No cleanup job exists.** Add the daily pg-boss job that deletes uploaded-but-unattached return photos older than 24 hours (and their R2 objects). Idempotent.
8. Confirm the bucket prefix is **private** (no public URL for `returns/`); the admin must reach photos only through short-lived signed URLs. If `R2_PUBLIC_URL` serves the whole bucket, add a private prefix or bucket rather than weakening the rule. State what you found in the change record.
Tests (real database plus a fake storage client): no token, wrong token, another order's token, key outside the tenant prefix, missing object, SVG or GIF content, wrong magic bytes, 6th photo, oversize, unfinalized or foreign media id on a return request, per-order rate limit, cleanup job run twice.
